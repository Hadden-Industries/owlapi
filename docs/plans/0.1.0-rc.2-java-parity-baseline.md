## Resource and performance decision boundary

Callers may explicitly set custom limits; loader and profile defaults remain unchanged.
Materialize callbacks, iterables and map inputs before publication or output commit; rejection never publishes partial state/text.

A new work-counter limit or changed numerical default is not selected without workload measurements and a narrow owner decision.
Before algorithms depending on such limits are admitted, retain measured representative/upper-limit fixture identities, timings, memory method and the proposed finite bound.

Use one warm-up and five measured runs and the existing applicable median/20-percent regression policy; new operation comparisons need their own matched baseline rather than an invented universal threshold.
