# Native storage observation boundaries for rc.2

Status: owner accepted on 2026-10-09: "3. I approve", in response to the mobile decision walkthrough.

These observations use freshly built Java revision `b61ebe2da83daceebb3e7ba7afbd2582c9240c33`.
They do not authorize dropping structural content or weakening the existing independent oracle.

| ID               | Reproducible native behavior                                                                                                                                                                                                                                            | Proposed producer treatment                                                                                                                                                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| RC2-STO-DIFF-001 | Java's OWL/XML parser drops an anonymous individual inside `ObjectOneOf`. The Java storer's own output has the same loss on Java reload. The all-kinds probe retains its named member and loses the anonymous member of the disjoint-union operand.                     | Keep the W3C `Individual` grammar and the complete anonymous operand in JS output. Require JS structural round-trip equality, inspect the actual XML operand, and use independent Java equality on the common domain. Record the precise native failure separately.            |
| RC2-STO-DIFF-002 | Java reconstructs the nested ontology annotation from Turtle, but reports its three `owl:annotatedSource`, `owl:annotatedProperty` and `owl:annotatedTarget` triples as unparsed metadata. The native Turtle storer emits the same W3C `owl:Annotation` representation. | Preserve the shared W3C RDF mapping. Require full structural equality and zero network attempts; retain the oracle's `OUTPUT_UNPARSED_RDF` result for this exact annotation case. Do not relabel that result as a clean oracle pass or relax the general unparsed-triple gate. |

`util/owlapi-reference/RunRC2Storage.java` uses only public save/load APIs to isolate these observations.
Its optional isolation argument changes only the probe ontology ID to an unrelated HTTP IRI, avoiding a separate native relative-URN serialization error while testing anonymous enumeration members.
Missing declarations added by the native storer are also recorded separately.

The W3C OWL/XML grammar admits both named and anonymous individuals in `ObjectOneOf`: <https://www.w3.org/TR/owl2-xml-serialization/>.
Nested ontology annotations use the annotation reification mapping: <https://www.w3.org/TR/owl2-mapping-to-rdf/>.
Acceptance must remain specific to these native defects, their fixture inputs and their observed differences; it cannot waive arbitrary storage mismatches.
