# rc.2 profile expected differences

This bounded decision applies to profile constraints only, under DEC-003 of the accepted Java parity plan.
W3C profile grammar owns conformance; the pinned Java oracle remains the comparison authority for all other common-domain cases.

The project-owned `RunRC2Profiles.java` harness and `util/owlapi-reference/fixtures/rc2/profile-observations.json` retain inputs and public results.
The observations have been confirmed against a fresh, source-bound local Windows build of the pinned Java revision.
This does not claim equivalence to the maintained Linux reference image; the final candidate still requires its own fixture and runtime bindings.

| Identity         | Native observation                                                                                                                                                  | Normative requirement and proposed result                                                                                                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RC2-PRF-DIFF-001 | RL rejects declarations of `xsd:unsignedInt` and `xsd:unsignedShort`.                                                                                               | W3C OWL 2 Profiles §4.2.1 explicitly admits both. Accept them, with all other DL and RL checks still applied.                                                                                                                                              |
| RC2-PRF-DIFF-002 | RL accepts a positive assertion using `owl:topObjectProperty` and a data assertion using `owl:bottomDataProperty`.                                                  | W3C §4.2.1 excludes the top and bottom object and data properties. Reject all four wherever used, including declarations and assertions.                                                                                                                   |
| RC2-PRF-DIFF-003 | EL rejects a chain whose last property inherits the required range through an ordinary subproperty edge (`chainRangeInherited`).                                    | W3C §2.2.6 defines imposed range through zero or more subproperty steps. Accept when the last property's inherited ranges include every range imposed on the chain head. Equivalence contributes both subproperty directions. Missing ranges still reject. |
| RC2-PRF-DIFF-004 | RL rejects disjoint-class operands using union, existential object/data restrictions or individual enumerations, although it accepts these as subclass expressions. | W3C §4.2.5 expressly uses `subClassExpression` for `DisjointClasses`. Apply the same complete subclass grammar to disjoint operands, including nested expressions. Do not substitute the equivalence grammar.                                              |

No expected difference suppresses a DL violation, incomplete closure, resource exhaustion, cancellation, stale snapshot or unsupported source assessment.
Comparisons must name the exact identity and check the proposed result directly; they must never convert a mismatched observation into an unconditional pass.

Authority: [W3C OWL 2 Profiles](https://www.w3.org/TR/owl2-profiles/), sections 2.2.6 and 4.2.1.
Owner accepted all four differences on 2026-10-09: "1. I approve", in response to the mobile decision walkthrough.
This acceptance is limited to the four identities above and their direct positive/negative controls.

The four identities govern new EL/QL/RL grammar differences.
The accepted baseline also retains the existing formal DL report and source-assessment conventions.
Every new profile still runs those existing DL checks; the statement above that no expected difference suppresses a DL violation applies even when the native EL/QL/RL checker omits that check.
These inherited checks are not additional new profile exceptions: `DATATYPE_DEFINITION_COUNT`, `LITERAL_LEXICAL_SPACE`, `TOP_DATA_PROPERTY_POSITION`, `DATA_RANGE_ARITY`, `ANONYMOUS_INDIVIDUAL_POSITION`, `ANONYMOUS_GRAPH_NOT_FOREST`, `MULTIPLE_ANONYMOUS_EDGE_ASSERTIONS`, and `ANONYMOUS_TREE_WITHOUT_ROOT` retain the existing validator's behavior.
The native `definedRestriction` exception is retained as an observation, while JS returns its existing invalid formal report.
Unknown annotation datatypes retain the existing invalid/incomplete assessment rather than receiving a new certification. The exact positive/native-omission controls are in `profiles/rc2Profiles.test.js`, alongside `profiles/owl2DLProfile.test.js`; none turns an oracle mismatch into a parity pass.
