## 1. Current direction and executive contract

This document is the single self-contained implementation authority for two coupled goals ahead of the `0.1.0` public release: (1) bringing `@hadden-industries/owlapi` peak working set and retained memory to practical parity with Java OWLAPI 5.5.1 across load, retention, queries, mutations, merging, OWL 2 profile checks, locality extraction, and serialization, and (2) replacing the format-coupled pre-`0.1.0` stream helpers introduced in commit `5135af93b4677ece6ebe2e26d2abafdea1a7be33` with format-orthogonal streaming I/O.

1. **Cut over `owlapi/io` streaming to format-orthogonal transport before `0.1.0` (`DEC-002`, `SLICE-002`).**
   Remove `RDFXMLStreamDocumentSource` ([rdfXmlStreamDocumentSource.js](../../io/rdfXmlStreamDocumentSource.js)) and `FunctionalSyntaxStreamDocumentTarget` ([functionalSyntaxStreamDocumentTarget.js](../../io/functionalSyntaxStreamDocumentTarget.js)) cleanly without compatibility shims or aliases (`NSH-01`, `NAM-01`).
   Replace them with format-agnostic `StreamDocumentSource` and `StreamDocumentTarget` aligned with Java OWLAPI’s `org.semanticweb.owlapi.io.StreamDocumentSource` and `org.semanticweb.owlapi.io.StreamDocumentTarget`, symmetrical over UTF-8 `Uint8Array` byte chunks, with zero public mutator methods on `StreamDocumentTarget.prototype` (`PARITY-TARGET-WRITER-OMISSION`).
   Upgrade [NodeDocumentLoader](../../io/node/nodeDocumentLoader.js) to return streamed sources for local `file:` and eligible streamed HTTP documents so `loadOntologyFromOntologyDocument(iri)` handles inputs exceeding V8’s `~512 MiB` single-string ceiling (`0x1fffffe8` UTF-16 code units) directly.
   Retain the deep internal streaming parsers and chunked writers built in `5135af93`.

2. **Eliminate ingress format disparity and 7-way post-ingress overlap (`DEC-003`, `SLICE-003`).**
   Generalize [CompactDefaultGraph](../../internal/rdfjs/compactDefaultGraph.js) into multi-graph-capable `CompactRdfGraph` (`~62 B/triple`) and route every RDF parser (`RDF/XML` string and stream, `Turtle`, `TriG`, `N-Triples`, `N-Quads`, `JSON-LD`) into it instead of `@rdfjs/dataset` (`~1,254 B/triple`, `20.2×` larger).
   Add package-branded integer row cursors to [rdfReadView.js](../../internal/mapping/rdfReadView.js) while preserving foreign RDF/JS `DatasetCore` getter fallback and exact `execution.check()` cadence.
   Cache `termId -> IRI` mappings per parse session (`4 B/term`) and publish directly through a single ownership-transferring `OntologyBuildBuffer` that releases `CompactRdfGraph` before sealing committed [ontologyState.js](../../internal/model/ontologyState.js).

3. **Keep slim, identity-preserving `OWLStructuralObject` values backed by `StructuralHashTable` (`DEC-004`, `SLICE-004`).**
   Do **not** replace OWL objects with custom UTF-8 byte-slab arenas plus transient flyweight wrappers or ES6 per-kind subclasses.
   Instead, mirror Java OWLAPI 5.5.1 / HotSpot CompressedOops physics directly on V8 pointer compression: retain exact `OWLStructuralObject.prototype` and `IRI.prototype`, strip the five cached tuple/JSON-string private fields (`#key`, `#keyWithoutAnnotations`, `#componentsWithoutAnnotations`, `#annotationBodyTuple`, `#tuple`), and avoid unnecessary per-object `PropertyArray` / `WeakSet` hash-slot growth so slim immutable objects drop to `~48–80 B` (vs `331 B` `IRI` and `913 B` `SubClassOf` today) while preserving `WeakMap` object identity ([sourceArity.js](../../internal/model/sourceArity.js), [structuralValidation.js](../../internal/model/structuralValidation.js)), `Object.freeze`, and `O(1)` reads.
   Encapsulate integer hashing, zero-allocation exact UTF-16 canonical ordering (matching `structuralKey()` bit-for-bit without `JSON.stringify` keys), open-addressed `StructuralHashTable` (`Int32Array` buckets + `Uint32Array` hashes + dense `values[]`), CSR builders, and dense bitsets inside a new deep internal module `internal/collections/`.

4. **Replace nested object read-model indexes with `Uint32Array` CSR postings and `O(Δ)` delta layers (`DEC-005`, `SLICE-005`).**
   Build lazy `Uint32Array` Compressed Sparse Row (`CSR`) indexes over dense `0` through `N - 1` `axiomId` and `entityId` ordinals inside [ontologyReadModel.js](../../internal/model/ontologyReadModel.js), eliminating `+167` to `+482 B/axiom` nested `Map`/`StructuralSet` graphs.
   Represent post-load manager edits in [ontologyState.js](../../internal/model/ontologyState.js) via tombstone bitsets and small added tables with bounded compaction.

5. **Eliminate downstream profile, locality, merge, and XML-DOM writer memory spikes (`DEC-006`, `SLICE-006`).**
   Remove permanent module-level `WeakMap` caches in [owl2dl.js](../../internal/profiles/owl2dl.js) (`preparedTraversals`, `+890 B/axiom`) and [syntacticLocalityModuleExtractor.js](../../modularity/locality/syntacticLocalityModuleExtractor.js) (`preparedAxioms`, `+423 B/axiom`), move internal consumers ([owlOntologyMerger.js](../../util/owlOntologyMerger.js), storers, search) onto package-private `readOntologyModel` iterators instead of allocating intermediate `getAxioms()` `Set`s, route [owlToRdfTranslator.js](../../internal/mapping/owlToRdfTranslator.js) through `CompactRdfGraph`, and replace whole-document `@xmldom/xmldom` DOM construction in [rdfXmlGraphWriter.js](../../internal/storage/rdfxml/rdfXmlGraphWriter.js) and [owlXmlStorer.js](../../internal/storage/owlxml/owlXmlStorer.js) (`+96.2 MiB` RSS on `2.35 MiB` output) with streaming UTF-8 XML token writers.

6. **Subject any further axiom packing (`DEC-007`) to a strict software-engineering and architectural best-practice gate — not a performance-only trigger — and keep SQLite / Wasm / native addons out of parity scope.**
   Do not bolt a dual-representation columnar side-table onto `StructuralAxiomSet` merely to chase a benchmark ratio; any representation beyond uniform slim `OWLStructuralObject` instances is admissible only if it improves conceptual integrity, module depth, and uniform invariants as well as measured memory, under explicit owner review (`OUT-01`).

## 2. Purpose anchor and motivation-to-evidence model

### Purpose anchor (`OUT-01`)

- **Beneficiaries:** Node.js (`>=22.0.0`) and browser (ES module import maps, application bundlers, and dedicated Web Workers) consumers of `@hadden-industries/owlapi`, including Universal Ontology ([java-parity-for-universal-ontology.md](../requirements/java-parity-for-universal-ontology.md)), WebVOWL ([java-parity-for-webvowl.md](../requirements/java-parity-for-webvowl.md)), and the cross-engine reference verification pipeline.
- **Desired result:** Lower cold-load peak working set, retained model RAM, downstream index/profile/locality deltas, and save spikes to practical parity with Java OWLAPI 5.5.1 (`≤1.5×` Java peak working set on paired equivalent workloads, with `≤2.0×` accepted only where a separately measured public defensive `Set` contract imposes an irreducible V8 floor), while preserving `≤1.10×` Java wall-time parity ([remaining-java-performance-implementation-results.md](../performance/remaining-java-performance-implementation-results.md)) and orthogonal streaming transport in `owlapi/io`.
- **Cost of inaction (do-nothing option):** Real OBO ontologies consume `6.96×–9.97×` Java peak RAM (`5.755–8.658 GiB` vs `0.819–0.887 GiB`), failing standard browser tab/worker memory ceilings and 8 GiB CI runners; `obo-gaz` reaches `15.85 GiB` process HWM at load completion; shipping `0.1.0` with `RDFXMLStreamDocumentSource` and `FunctionalSyntaxStreamDocumentTarget` commits the public API and cryptographic governance ledger to a `Transport × Format` anti-pattern.
- **Guardrails and explicit non-goals:** No new unapproved public methods on `OWLOntology` (`PAR-001`, `PAR-002`); no compatibility shims or aliases (`NSH-01`); no native C++ addons (`better-sqlite3`, `roaring`), Wasm stores (`oxigraph`, `@sqlite.org/sqlite-wasm`, `roaring-wasm`), or `node:sqlite`; no raising `"node": ">=22.0.0"`; no weakening of DTD/entity caps, host/SSRF authorization, `AbortSignal`/deadline checkpoints, `preserve`-mode source fidelity, or dual-profile parity (`java-owlapi-5.5.1` and `normative-v1`).

### 3.2 Node `26.13.1` memory attribution on synthetic OBO fixtures (`97b452d4`)

Targeted V8 probes on Node `v26.13.1` explain the exact mechanisms behind the `+14.62 GiB` expansion:

1. **Ingress RDF storage density (`bytes/triple`):**
   - `@rdfjs/dataset` (`DatasetCore`, currently used on `StringDocumentSource` for RDF/XML and all N3/JSON-LD parses): **`~1,254 B/triple`**.
   - `N3.Store` (`n3@2.13.12`): **`~1,208 B/triple`**.
   - `CompactDefaultGraph` ([compactDefaultGraph.js](../../internal/rdfjs/compactDefaultGraph.js), used only on `RDFXMLStreamDocumentSource`): **`~62 B/triple`** (`20.2×` smaller than `@rdfjs/dataset`).
2. **Load high-water mark vs post-GC retained ontology (`2,000` classes, `12,002` axioms, `28,000` triples):**
   - `StringDocumentSource` peak V8 heap: **`168.14 MiB` (`14,690 B/axiom`)**;
   - `RDFXMLStreamDocumentSource` peak V8 heap: **`86.48 MiB` (`7,556 B/axiom`)**;
   - Post-GC retained `OWLOntology`: **`16.14 MiB` (`1,410 B/axiom`)**;
   - Clean isolated function release drops V8 heap back to **`8.35 MiB`** baseline (confirming transient overload rather than a permanent global leak).
3. **Why stream peak is `5.36×` retained (`7,556` vs `1,410 B/axiom`):** Seven live representations overlap in [rdfReadView.js](../../internal/mapping/rdfReadView.js), [rdfToOwlTranslator.js](../../internal/mapping/rdfToOwlTranslator.js), and [owlOntologyManager.js](../../model/owlOntologyManager.js): (1) packed/object RDF store, (2) materialized frozen `collect()`/`outgoing()` quad arrays plus translator role/reification/list/expression `Map` and `Set` indexes, (3) `ParseTransaction` `StructuralSet`s, (4) `acceptedAxioms` array batches, (5) provisional ontology state, (6) `publishLoadedState` validation and re-indexed `StructuralAxiomSet`, and (7) source-role/evidence structures.
4. **Differential `v8.getHeapSnapshot()` breakdown of retained ontology (`9,002` axioms, `~35.5 B/axiom` raw UTF-8 semantic payload):**

| Retained V8 owner                                                                                       | Retained bytes / axiom | Share of retained heap | Root mechanism in snapshot `97b452d4`                                                                                                                                       |

## 4. Software selection and reuse assessment (`REU-01`, `VER-01`, `LIC-01`)

### Software selection record: Compact OWL/RDF storage, bitsets, and stream transports

## 5. Architectural smells and rejected design paths

To prevent re-introducing high-risk shortcuts during implementation, the following mechanisms are explicitly prohibited:

1. **Format-Coupled Public Stream Classes (`RDFXMLStreamDocumentSource`, `FunctionalSyntaxStreamDocumentTarget`).**
   These exports committed five design defects in `5135af93`:
   - *Combinatorial `Transport × Format` coupling:* Java OWLAPI (`org.semanticweb.owlapi.io.StreamDocumentSource` and `org.semanticweb.owlapi.io.StreamDocumentTarget` in Java OWLAPI 5.5.1 source `f760b3a4c107c6d5f90f856e5680c39b18af646f`) and JS [StringDocumentSource](../../io/stringDocumentSource.js) / [StringDocumentTarget](../../io/stringDocumentTarget.js) separate *transport* from *syntax format*.
     Hardcoding `getFormat() { return OWLDocumentFormats.RDF_XML; }` and rejecting every format except Functional Syntax in [storerRegistry.js](../../internal/storage/storerRegistry.js) would force `2 × N` classes or broken Liskov substitution once `RDF/XML`, `OWL/XML`, and `Turtle` stream in `SLICE-006`.
   - *Benchmark-harness leakage:* [run-comparison-js.mjs](../../util/owlapi-reference/run-comparison-js.mjs) needed `RDF/XML in → Functional Syntax out`, which was exported verbatim as `0.1.0` public library classes ([API.md](../../API.md), [README.md](../../README.md)).
   - *Leaked `@internal` mutator & type asymmetry:* `FunctionalSyntaxStreamDocumentTarget` exposes `prototype.writeChunks` publicly despite marking it `@internal`—contravening `PARITY-TARGET-WRITER-OMISSION` in [java-api-parity-decisions.json](../compatibility/java-api-parity-decisions.json) ("expose no mutator")—while taking `string` chunks where the source yields `Uint8Array`.
   - *Manager `instanceof` special cases & unstreamed loader:* [owlOntologyManager.js](../../model/owlOntologyManager.js) bypasses `#checkInputSize` via `instanceof RDFXMLStreamDocumentSource` while [nodeDocumentLoader.js](../../io/node/nodeDocumentLoader.js) still materializes strings via `StringDocumentSource`.
   - *Why reverting to strings-only is also impossible:* V8’s maximum string length (`0x1fffffe8` chars, `~512 MiB` UTF-16) physically prevents `StringDocumentSource` or `StringDocumentTarget` from loading `1.31 GiB` GAZ or emitting `1.15 GiB` Functional Syntax.
     Removing the two format-coupled classes before `0.1.0` ships and replacing them with format-agnostic, byte-symmetrical `StreamDocumentSource` and `StreamDocumentTarget` preserves streaming capacity with clean orthogonality.

2. **Custom UTF-8 Byte-Arena + Lazy Flyweight `CanonicalOntologyStore` (Second-System Trap).**
   Materializing transient flyweights from custom UTF-8 byte slabs destroys `WeakMap` / `WeakSet` object identity (`retainSourceArity` in [sourceArity.js](../../internal/model/sourceArity.js) for `preserve`-mode singleton boolean/set arities, plus `validatedShapes` / `validatedStructureNodes` in [structuralValidation.js](../../internal/model/structuralValidation.js)), causes `TextDecoder.decode()` + `Object.freeze()` thrashing on every query/profile/duplicator pass (threatening `≤1.10×` latency parity), and duplicates all 62 OWL structural kinds into a secondary binary schema.

3. **Per-Kind ES6 Subclasses (`SlimIRI`, `SlimSubClassOf`, ...).**
   [validateStructuralShape](../../internal/model/structuralValidation.js) and `isPackageOwnedStructuralObject` ([ontologyState.js](../../internal/model/ontologyState.js)) reject any value whose prototype is not strictly `IRI.prototype` or `OWLStructuralObject.prototype`, and [structural.js](../../model/structural.js) documents that subclasses require a separate public API decision.
   Furthermore, V8 already creates distinct monomorphic hidden classes (`Map`s) on `OWLStructuralObject` when factories assign own data fields in fixed order without ES6 subclassing.

4. **UTF-8 Byte Order or Naive Field-String Order in Set Normalization & Deterministic Writers.**
   [structural.js](../../model/structural.js), [model.test.js](../../model/model.test.js), and [governance.test.js](../../governance.test.js) define ordering via UTF-16 code units on `structuralKey()`.
   UTF-8 byte order inverts supplementary code points (`U+10000+`) against `U+E000–U+FFFF`.
   Worse, even on ASCII, raw string order diverges from `JSON.stringify` tuple order: in `'["Class",["IRI","a"]]'` vs `'["Class",["IRI","a!"]]'`, closing quote `"` (`0x22 = 34`) sorts *after* `'!'` (`0x21 = 33`) and space (`0x20 = 32`), so `"a!" < "a"` in `structuralKey()` order!
   Changing `normalizeStructuralSet` order silently changes canonical equality and deterministic output snapshots; therefore `internal/collections/` must implement exact zero-allocation `structuralKey()` token order (`DEC-004`).

5. **Global `WeakRef` + `FinalizationRegistry` Interning in `IRI.create()`.**
   In V8, `WeakRef` + `FinalizationRegistry` `WeakCell` + `Map` bucket overhead runs `~112–128 B` per entry—`2.5×` more RAM than a `48 B` slim `IRI`—while introducing macrotask reclamation lag and global state in leaf module [structural.js](../../model/structural.js).
   Scoped `OWLDataFactory` `Map` interning plus per-parse `termId -> IRI` arrays (`4 B/slot`) achieve reuse at `30×` lower cost.

6. **Putting Loaded Axioms into `WeakSet`s (`validatedShapes`) & Ignored Fast-Path Guards.**
   In V8, calling `WeakSet.add(frozenObj)` or `WeakMap.set(frozenObj, ...)` on all `7.8M` frozen axioms forces allocation of an identity hash in every object’s `PropertyArray` (`~24–40 B` each, adding `~180–310 MiB` on GAZ alone!).
   Internal manager-constructed snapshots must admit provenance at the **snapshot** boundary (`validatedGraphs` 1 entry per ontology), reserving per-object `WeakMap`s solely for rare `sourceArity` nodes (`<0.01%`) and external untrusted inputs.
   Every fast path must guard on `isCompactRdfGraph`, `isNativeGroundStructuralObject`, `nativeStructuralMethods`, and preserved `execution.check()` counts ([remaining-java-performance-implementation-results.md](../performance/remaining-java-performance-implementation-results.md)).

7. **Unapproved Public `OWLOntology` Iterators (`PAR-001` / `PAR-002`), Speculative `SpillStore`, and Multi-Seam Big-Bang Rewrite.**
   Public convenience methods violate `PAR-001`/`PAR-002` and [governance.test.js](../../governance.test.js); internal consumers use `readOntologyModel()`.

## 7. Architectural decisions, `DRY-01` audit, and `NAM-01` audit

### `DEC-001` — Host-guarded paired measurement protocol and GAZ load-only Java baseline (`RES-01`)

- **Status:** Owner confirmed on `2026-11-24`.
- **Problem:** A `97b452d` Windows diagnostic/benchmark process exhausted host commit during an unguarded run, and Java’s recorded `11.02 GiB` GAZ number bundles load, Functional Syntax reparse, and isomorphism diff in one JVM process while JS `15.85 GiB` is load-completion only.
- **Design contract:**
  1. Add a `--load-only` / phase-isolated verification option to the Java and JS comparison runners (`util/owlapi-reference/RunOntologyComparisonCase.java` and `util/owlapi-reference/run-comparison-js.mjs`) that records ontology ID, annotation count, axiom count, and canonical summary witness/digest at load completion without running a second in-process Functional Syntax reparse when measuring load-only peak RAM.
  2. Enforce host safety in the runner launcher (`RES-01`): verify sufficient free physical RAM and commit charge before spawning a heavy process (`obo-gaz`), run heavy Java and JS processes strictly sequentially (never concurrently), pass explicit Node `--max-old-space-size` and JVM `-Xmx` values captured in run provenance, and launch child trees inside a Windows Job Object with an explicit process-tree commit cap (`JOB_OBJECT_LIMIT_JOB_MEMORY` or helper guard) so runaway allocations fail inside the child process instead of exhausting the host.
  3. Separate **clean production memory/timing runs** (recording `maxRSS` / `PeakWorkingSetSize`, post-load `process.memoryUsage()` fields `{ rss, heapTotal, heapUsed, external, arrayBuffers }`, and wall time across `≥3` alternating trials) from **diagnostic `--heap-prof` / `--expose-gc` / `v8.getHeapSnapshot()` runs** (used strictly to attribute owners and verify post-GC retention; never mix snapshot/GC hooks into timing or peak-RAM qualification numbers, noting Node’s documented `~2×` heap spike during `getHeapSnapshot()`).
  4. Report `getAxioms()` `Set` materialization peak as its own post-load checkpoint distinct from load/retention peak.
- **Owner / local discretion:** Choice of PowerShell/Win32 Job Object P/Invoke helper vs small isolated runner wrapper script remains local implementation discretion so long as child termination and headroom checks are verified with a bounded over-allocation probe (`QA-007`).

### `DEC-002` — Orthogonal `StreamDocumentSource`, `StreamDocumentTarget`, and `NodeDocumentLoader` streaming (`NAM-01`, `NSH-01`, `VAL-01`)

- **Status:** Owner confirmed on `2026-11-24`.

- **Contract (`StreamDocumentSource` in `io/streamDocumentSource.js`, exported from `io/index.js` and `index.js`):**

  - **`NodeDocumentLoader` streaming (`io/node/nodeDocumentLoader.js`):** Keep existing DNS-pinning, SSRF blocklist, HTTP `authorize()`, and timeout/abort enforcement untouched.

- **Contract (`StreamDocumentTarget` in `io/streamDocumentTarget.js`, exported from `io/index.js` and `index.js`):**
  Contract signature: `new StreamDocumentTarget(sink)`.
  - **Inputs and validation:** Reject non-function `sink` with `TypeError`.

### `DEC-004` — Slim identity-preserving `OWLStructuralObject`, `internal/collections/`, and zero-alloc UTF-16 comparator

- **Problem:** Retaining `#tuple` arrays (`456 B/axiom`), lazy `#key` JSON strings (`195.5 B/axiom`), and six private-field `PropertyArray`s (`40 B/instance`) inflates retained JS objects by `~10–14×` vs Java OWLAPI 5.5.1.
- **Contract:**
  1. **New deep internal module `internal/collections/`:**

       Back both `StructuralSet` and `StructuralAxiomSet` (plus annotationless-body equivalence when needed) with this table.
     - `csrPostingIndex.js` & `denseBitSet.js`: Compressed Sparse Row (`offsets: Uint32Array`, `entries: Uint32Array`) builder and 32-bit-word `Uint32Array` bitset utilities.
     - *Lint & architecture isolation:* Grant `"no-bitwise": "off"` in [eslint.config.js](../../eslint.config.js) **exclusively** for `internal/collections/**/*.js` (with an explanatory comment under `DOC-01`), and bind strict layering in [.dependency-cruiser.json](../../.dependency-cruiser.json) so `internal/collections/` has zero upward imports except `model/kinds.js` and `internal/model/structuralFields.js` (keeping structural primitives leaf-isolated).
  2. **Slim `OWLStructuralObject` & `IRI` ([model/structural.js](../../model/structural.js)):**
     - **Preserve prototypes (`IRI.prototype`, `OWLStructuralObject.prototype`), `Object.freeze(value)`, exact own data-property keys matching `structuralFields`, and public methods (`structuralKey()`, `toStructuralTuple()`, `equals()`, `structuralKeyWithoutAnnotations()`, `equalsIgnoreAnnotations()`, `getAxiomWithoutAnnotations()`, `getAnnotatedAxiom()`).**
     - **Delete `#key`, `#keyWithoutAnnotations`, `#componentsWithoutAnnotations`, `#annotationBodyTuple`, and `#tuple`.**
       Compute `toStructuralTuple()`, `structuralKey()`, and `structuralKeyWithoutAnnotations()` strictly on demand when a caller invokes them (returning fresh frozen tuples matching current semantics, never retaining strings or arrays on native model nodes).
     - **Factory-scoped `IRI` interning ([owlDataFactory.js](../../model/owlDataFactory.js)):** Intern `IRI`s in `OWLDataFactory` (alongside `#entities`), avoiding global `WeakRef` / `FinalizationRegistry` overhead (`~120 B/entry`).
     - **Mandatory `SLICE-004` discriminating experiment on private-slot V8 cost & `WeakSet` brand preservation:**
       As established in §3.2 and §5.6, declaring *any* ES private field (`#brand`) or inserting all `7.8M` frozen objects into a `WeakSet` (`validatedShapes`) can trigger V8 out-of-object `PropertyArray` allocation (`+24–40 B/object` = `+180–310 MiB` on GAZ!).
       Before committing the final brand representation in `SLICE-004`, benchmark two candidate layouts on `100,000` frozen `SubClassOf` + `IRI` objects in Node `26.13.1`:
       - *Candidate A:* Zero `#private` fields on `OWLStructuralObject` / `IRI`; keep a single non-enumerable `Symbol` brand property OR fast-path prototype/structural descriptor check + snapshot-level `validatedGraphs` admission (`1` `WeakMap` entry per ontology snapshot rather than `7.8M` `validatedShapes.add(axiom)` calls), ensuring forged `Object.create(OWLStructuralObject.prototype)` lookalikes still fail `structuralKey.call(fake)` / `copyAxiomAnnotations(fake)` / `IRI.create(fake)` security tests ([model.test.js](../../model/model.test.js)).
       - *Candidate B:* Single `#flags` SMI private field on `OWLStructuralObject` (measuring exact V8 byte delta vs Candidate A in `--expose-gc` heap snapshot).
         Select the smaller layout that passes every forged-object and prototype-override security test, and **unconditionally remove bulk `validatedShapes.add(axiom)` calls** from internal manager-constructed snapshot paths (`ontologyState` / `owl2dl.js` / `syntacticLocalityModuleExtractor.js`), retaining `validatedShapes` only for external caller-supplied values (`VAL-01`).

## 8. Vertical implementation slices

### Security, trust boundaries, and compatibility constraints (`SEC-01`, `VAL-01`, `RES-01`)

1. **Input-size and XML entity limits prior to heavy allocation:** Pre-decode `maxInputBytes` counting in shared `streamByteReader.js` blocks memory exhaustion on huge/malformed `StreamDocumentSource` inputs for **all** parsers before UTF-8 string/quad materialization.
   Existing DTD/entity expansion protections (`xmlEntityPolicy.js`), DNS-pinning/SSRF controls (`nodeDocumentLoader.js`), and default remote-import denial remain invariant.
2. **Prototype/proxy impersonation resistance:** Unforgeable native structural checks (`model.test.js` malformed `IRI` / constructor `Proxy` checks, `StringDocumentTarget` / `StreamDocumentTarget` `WeakMap`-protected mutators, and forged `OWLStructuralObject.prototype` rejection in `structuralValidation.js` / `ontologyState.js`) must remain unbroken under `SLICE-002` and `SLICE-004`.
3. **Adversarial hash-collision protection:** `structuralHash.js` mixes a non-predictable per-process/per-table 32-bit random seed into bucket indices so crafted URI/IRI workloads cannot degrade `StructuralHashTable` or CSR lookups to `O(N^2)`, while deterministic outputs use `compareStructuralValues` rather than hash bucket order.
4. **Release governance & package boundaries:** All edits under `internal/` and `io/` update [reference-import-map.json](../../test/consumers/browser/import-map/reference-import-map.json) provider-only bundle checks via `npm run prepare:browser-consumers`, pass `eslint --config eslint.json-identity.config.mjs`, preserve `"node": ">=22.0.0"`, and produce clean SBOMs (`npm run generate:release-sbom`).
