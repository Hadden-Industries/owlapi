# Dependency version ownership

Each dependency version is declared in one file.
Every other occurrence is either generated from that declaration and checked for drift, or a recorded fact.

| Dependency                                                   | Authority                                                                            | Generated or checked consumers                                                                                                                                                                       | Update procedure                                                                                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Node references, producer and consumer npm, consumer runners | [`docs/release/runtime-policy.json`](../release/runtime-policy.json)                 | `package.json` engine fields, `.node-version`, producer obligations, the install-script npm version, the README and contributor runtime blocks, workflow job names, runner labels and runner records | Run `npm run sync:node`; `npm run check:node` rejects drift.                                                                        |
| GitHub Actions                                               | [`docs/release/action-versions.json`](../release/action-versions.json)               | Every external `uses:` reference in workflows and composite actions, and the workflow governance pin checks                                                                                          | Run `node scripts/project-action-versions.mjs --write`; workflow governance rejects drift, unregistered actions and unused entries. |
| uv                                                           | [`docs/release/development-tools.json`](../release/development-tools.json)           | `required-version` in both Python projects, the checksum-pinned bootstrap and the third-party material record                                                                                        | Run `node scripts/sync-python-target.mjs --write`, then regenerate both locks with the selected uv.                                 |
| actionlint                                                   | [`docs/release/development-tools.json`](../release/development-tools.json)           | The CI install step's version, archive name and digest                                                                                                                                               | Run `npm run sync:node`.                                                                                                            |
| CPython                                                      | [`.python-version`](../../.python-version)                                           | `requires-python` in both Python projects, the Ruff target and scanner metadata                                                                                                                      | Run `node scripts/sync-python-target.mjs --write`.                                                                                  |
| Ruff                                                         | [`pyproject.toml`](../../pyproject.toml)                                             | `uv.lock` and the third-party material record                                                                                                                                                        | Regenerate the lock, then run `node util/generate-third-party-material.mjs --write`.                                                |
| ScanCode and Beartype                                        | [`util/scancode-runtime/pyproject.toml`](../../util/scancode-runtime/pyproject.toml) | Its `uv.lock`, the scanner install path in workflows, evidence and governance checks, and the third-party material record                                                                            | Regenerate the lock, run `npm run sync:node`, rebuild the scanner licence inventory and regenerate the material.                    |
| Temurin JDK                                                  | [`.java-version`](../../.java-version)                                               | `setup-java` reads it through `java-version-file`                                                                                                                                                    | Edit the file.                                                                                                                      |
| npm packages                                                 | [`package.json`](../../package.json)                                                 | The npm-generated `package-lock.json`                                                                                                                                                                | Install with npm, then refresh the dependency evidence.                                                                             |
| Shared npm overrides                                         | `overrides` in the root [`package.json`](../../package.json)                         | Matching overrides in the [artifact-transport manifest](../../tooling/artifact-transport/package.json)                                                                                               | Run `node scripts/project-shared-overrides.mjs --write`, then refresh that project's lock with npm.                                 |

GitHub requires literal action references, npm and uv read versions only from their own manifests, and lockfiles record exact resolutions.
Those copies are generated, so edit only the authority and rerun its projector.

Recorded facts keep the versions that produced them: changelog entries, dated plans, qualification and evidence records, versioned licence files and comments that describe behavior observed with a specific release.
Scanner evidence, for example, must be re-acquired when the ScanCode pin changes.
