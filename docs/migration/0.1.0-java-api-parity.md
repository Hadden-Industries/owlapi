# Java API migration for the latest release

This guide describes storage targets, errors and import closure composition in the [latest published release](../../README.md#release-status).
Use the [installation instructions](../../README.md#install) to save an exact dependency while retaining the `owlapi/*` imports below.
Direct scoped imports expose the same API.
UO and WebVOWL may accept this exact RC for production after their own qualification; stable `0.1.0` is not required.

The release includes [RDF/XML writer configuration](../compatibility/rdfxml-writer-configuration.md) and explicit [Java/normative behavior profiles](../compatibility/behavior-profiles.md).
The examples below use `normative-v1`, the default: mutation is atomic and failed storage leaves the target unchanged.
Java migrations must explicitly select `java-owlapi-5.5.1` and account for `ChangeApplied` results, sequential mutation, append storage and documented partial effects.
The [API delta](../compatibility/0.1.0-api-delta.md) records added exports and enlarged member surfaces.
Omitted or null profile `timeoutMs` disables its elapsed deadline; pass `30000` to retain the historical 30-second cutoff.

## Upgrading from rc.2 to rc.3

The package keeps its existing exports and adds `NodeDocumentLoader` from `owlapi/io/node` and `ChangeApplied` from `owlapi/model/parameters`.
The Node adapter requires an application-owned authorization callback; choosing a behavior profile does not grant file or network access.

Select a profile when constructing a manager, standalone factory, renderer or language-profile checker:

```js
import { OWLManager } from "owlapi/apibinding";
import { IRI } from "owlapi/model";
import { ChangeApplied } from "owlapi/model/parameters";

const manager = OWLManager.createOWLOntologyManager({
  behaviorProfileId: "java-owlapi-5.5.1",
});
const ontology = manager.createOntology();
const factory = manager.getOWLDataFactory();
const person = factory.getOWLClass(IRI.create("https://example.com/Person"));
const result = manager.addAxiom(ontology, factory.getOWLDeclarationAxiom(person));
console.log(result === ChangeApplied.SUCCESSFULLY); // true
```

The normative profile returns a boolean for changes and commits complete batches atomically.
Java-profile changes are sequential, and failures can leave earlier changes applied.
Java saves append to reused targets and can retain partial output on failure; normative saves replace complete output atomically.
Use a fresh target per save when the application needs independent outputs.

`EntitySearcher` results are deferred, single-use iterables in both profiles.
Call `Array.from(result)` to capture a reusable snapshot; repeated iteration of the original result does not replay it.
Closure providers query current managed state each time they are called.
Java-profile literals and RDF metadata follow native normalization and counting, while the normative profile preserves its separate lexical and header contract.

The Java profile adds no JavaScript-only finite default budgets, while normative loading keeps its finite ceilings.
Explicit host restrictions, cancellation and native provider limits remain available.
Use the [configuration comparison](../compatibility/behavior-profiles.md#configuration-and-resource-defaults) before accepting untrusted or large input.

## Saved text and storage errors

Two provisional spellings were rejected before their first public release.
There is no compatibility alias or forwarding export for either one.

| Provisional spelling                         | Accepted public contract                                           |
| -------------------------------------------- | ------------------------------------------------------------------ |
| `target.getText()` on `StringDocumentTarget` | `target.toString()`                                                |
| `UnrepresentableOntologyError`               | `OWLOntologyStorageError` with reason `ONTOLOGY_NOT_REPRESENTABLE` |

The valid `StringDocumentSource.getText()` reader is unchanged.
Check the receiver type before changing a `getText()` call.

```javascript
import { OWLDocumentFormats } from "owlapi/formats";
import { OWLOntologyStorageError, StringDocumentTarget } from "owlapi/io";

async function renderRdfXml(manager, ontology) {
  // This example's unchanged-target guarantee requires the normative profile.
  if (manager.getBehaviorProfileId() !== "normative-v1") {
    throw new TypeError("This example requires normative-v1");
  }
  const target = new StringDocumentTarget();
  try {
    await manager.saveOntology(ontology, OWLDocumentFormats.RDF_XML, target);
    return target.toString();
  } catch (error) {
    if (
      error instanceof OWLOntologyStorageError &&
      error.reason === "ONTOLOGY_NOT_REPRESENTABLE"
    ) {
      // The caller decides how to report this unsupported representation.
      // The target still contains exactly its pre-call text.
      throw error;
    }
    throw error;
  }
}
```

`saveOntology` is asynchronous and requires an explicit managed ontology, format and target.
`OWLStorerNotFoundError` extends `OWLOntologyStorageError` and reports an unsupported format selection.
Functional Syntax preserves the supported structural model; RDF/XML rejects a supported structure when its encoding would lose information, including the mandated non-injective annotation case.
Neither format silently falls back to another syntax.
Concrete storer classes and their registration remain private.
The capability matrix records implemented storage behavior, while each Java type's registry progress records its public class exposure.
Consequently, `storer.functional` and `storer.rdfxml` can be complete while the concrete Java storer class counterparts remain `NOT_STARTED` / `DEFERRED_NOT_EXPOSED`; this does not claim public constructors or registration APIs.

## Consumer-owned import closure composition

The following composes the Java-shaped primitives for a root already loaded with its complete import closure.
The input manager's resolver and admission policy belong to the application.

```javascript
import { OWLManager } from "owlapi/apibinding";
import { OWLDocumentFormats } from "owlapi/formats";
import { StringDocumentSource, StringDocumentTarget } from "owlapi/io";
import { AddOntologyAnnotation, SetOntologyID } from "owlapi/model";
import {
  OWLOntologyImportsClosureSetProvider,
  OWLOntologyMerger,
} from "owlapi/util";

async function renderClosure(inputManager, root) {
  const provider = new OWLOntologyImportsClosureSetProvider(inputManager, root);
  const outputManager = OWLManager.createOWLOntologyManager({ behaviorProfileId: "normative-v1" });
  const merged = new OWLOntologyMerger(provider, false).createMergedOntology(
    outputManager,
  );
  outputManager.applyChange(new SetOntologyID(merged, root.getOntologyID()));
  outputManager.applyChanges(
    [...root.getAnnotations()].map(
      (annotation) => new AddOntologyAnnotation(merged, annotation),
    ),
  );
  const target = new StringDocumentTarget();
  await outputManager.saveOntology(merged, OWLDocumentFormats.FUNCTIONAL, target);
  const text = target.toString();
  const verifier = OWLManager.createOWLOntologyManager({
    behaviorProfileId: "normative-v1",
    documentLoader: {
      load() {
        throw new Error("The collapsed output must reload without imports");
      },
    },
  });
  const reloaded = await verifier.loadOntologyFromOntologyDocument(
    new StringDocumentSource(text),
    { parsingMode: "strict" },
  );
  return { merged, reloaded, text };
}
```

The provider snapshots the retained manager closure without fetching documents.
The merger copies the full direct axiom union because its second argument is `false`; it does not copy imports or ontology annotations.
The example explicitly restores the root's complete identity and copies only its ontology annotations.
A successful strict reload establishes parseability; the consumer must also compare the complete structure under one anonymous-individual bijection, assert empty imports and zero loader calls, and enforce its own atomic output/publication policy.
The library does not export an application-specific materializer, catalog policy or filesystem publisher.
