## Implemented scope

Phase 17 promotes the distinct `KRSSOWLParser` compatibility surface from a
format identity into a production parser. A dialect-neutral lazy core now sits
behind separate KRSS1 and KRSS2 adapters. KRSS1 owns its smaller top-level set,
alphanumeric Name grammar, required primitive parents, required cardinality
fillers, lack of inverse-role expressions, exact format identity, descriptor,
detection policy, diagnostics, fixtures, and pinned Java oracle.

The default manager and production VOWL entry now accept explicit KRSS1 and
generic `.krss` documents. Exact `.krss2` remains KRSS2. Definite KRSS2-only
vocabulary excludes KRSS1, while shared syntax remains explicitly ambiguous.
No pre-cutover legacy parser is called and no dependency is added.

## Controlled compatibility decisions

`compatibility/krss1-behavioral-oracle.json` is the authoritative finite list.
It preserves the right-identity no-effect and unreachable full-IRI Name
boundary. It corrects Java's discarded ABox axioms, unreachable integer
cardinalities, malformed `Optional[...]` name base, and nonconforming singleton
Boolean object. No wildcard expected-difference rule is introduced.

## Performance and dependency impact

The accepted run measured 50,000 primitive concepts at 932.04 ms median and
256 nested existential restrictions at 74.32 ms median. Adding only the KRSS1
descriptor changed Functional-large wall/heap medians by -3.06%/+0.32% and the
16 MiB mismatch medians by +1.96%/+2.24%. The mismatch heap delta is 40,520
bytes. All remain within the unchanged 20% threshold and 64 KiB designated
selection ceiling. Phase 17 adds no dependency, lockfile, resource-ceiling, or
regression-threshold change.
